# Definitions

> 💡 NLP is a field of linguistics and machine learning (ML) focused on understanding everything related to human language. The aim is to not only understand single words, but be able to understand the context.

> 💡 Large Language Models (LLMs) are a powerful subset of NLP models characterised by massive size, extensive training data, and ability to perform a wide range of linguistic tasks with minimal specialised training.

# Natural Language Processing and Large Language Models

### What is NLP?

Common NLP tasks include
- Classifying whole sentences
- Classifying each word in a sentence
- Generating text content
- Extracting an answer from text
- Generating a new sentence from an input text

### Rise of LLMs

NLP has recently been revolutionised by LLMs. These models, including GPT and Llama, have transformed what's possible in language processing (LP).

LLMs are characterised by
- Scale
- General capabilities
- In-context learning
- Emergent abilities

However, LLMs also have important limitations, such as
- Hallucinations
- Lack of true understanding
- Bias
- Context windows
- Computational resources

### Why is LP Challenging?

Us as humans are easily able to find similarities between two sentences, for example "I am hungry" and "I am sad". This is a far more difficult task for machine learning (ML) models. The text needs to be carefully preprocessed in such a way that enables ML models to learn from it. There are also other challenges involved such as ambiguity, cultral context, sarcasm, and humor. These are usually addressed by increasing dataset diversity, but it's not yet perfect.

# Transformers

## What Can Transformers Do?

Transformers are used to solve all kinds of tasks, such as: NLP, computer vision, audio processing, and more.

The most basic object in the Hugging Face Transformers library is `pipeline()`. It connects a model with necessary preprocessing and postprocessing steps.

```py
from transformers import pipeline

classifier = pipeline("sentiment-analysis")
classifier("I've been waiting for a HuggingFace course my whole life.")
```

`pipeline()` supports multiple modalities, allowing working with text, images, audio, and even multimodal tasks.

Text pipelines support:
- `text-generation`
- `text-classification`
- `summarization`
- `translation`
- `zero-shot-classification`
- `feature-extraction`

## Zero-Shot Classification

Used when we need to classify text that hasn't been labelled. This is common in real-world projects because annotating text is time-consuming and typically requires domain expertise.

The `zero-shot-classification` is very powerful; it allows specifying which labels to use for classification, so you do not have to rely on labels of pretrained model.

```py
from transformers import pipeline

classifier = pipeline("zero-shot-classification")
classifier(
    "This is a course about the Transformers library",
    candidate_labels=["education", "politics", "business"],
)
```

## Text Generation

The main idea is that you provide a prompt and the model will auto-complete it by generating the remaining text, similar to the predictive text feature on many phones.

```py
from transformers import pipeline

generator = pipeline("text-generation")
generator("In this course, we will teach you how to")
```

You can control how many sequences are generated by supplying the argument `num_return_sequences`, and the total length of text with the argument `max_length`.

## Using a Specific Model in a Pipeline

The model can be specified by providing the `model` argument. Go to [Hugging Face Model Hub][(https://huggingface.co/models) and click on the corresponding  tag on the left to display only supported models for a specific task.

In the below example, the model [HuggingFaceTB/SmolLM2-360M](https://huggingface.co/HuggingFaceTB/SmolLM2-360M) is used.

```py
from transformers import pipeline

generator = pipeline("text-generation", model="HuggingFaceTB/SmolLM2-360M")
generator(
    "In this course, we will teach you how to",
    max_length=30,
    num_return_sequences=2,
)
```

## Mask Filling

This pipeline will fill in the blanks in a given text.

```py
from transformers import pipeline

unmasker = pipeline("fill-mask")
unmasker("This course will teach you all about <mask> models.", top_k=2)
```

The argument `top_k` controls how many possibilities should be returned. The models fill in the special `<mask>` word, which is often referred to as a *mask token*. Other mask-filling models may have different mask tokens, so it is important to verify the proper mask word when exploring other models.

## Named Entity Recognition

Named entity recognition (NER) is a task where the model must find which parts of the input text correspond to entities such as persons, locations, or organizations.

```py
from transformers import pipeline

ner = pipeline("ner", grouped_entities=True)
ner("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

```
[{'entity_group': 'PER', 'score': 0.99816, 'word': 'Sylvain', 'start': 11, 'end': 18}, 
 {'entity_group': 'ORG', 'score': 0.97960, 'word': 'Hugging Face', 'start': 33, 'end': 45}, 
 {'entity_group': 'LOC', 'score': 0.99321, 'word': 'Brooklyn', 'start': 49, 'end': 57}
]
```

The `grouped_entities=True` option tells the pipeline to regroup parts of the sentence that correspond to the same entity: Here the model correctly grouped "Hugging" and "Face" as a single organisation.

## Summarization

**Summarization** is the task of reducing a text into a shorter version while preserving the important information.

```py

```

Example output:

```py

```

Key notes:

* Produces concise summaries of long text
* Useful for articles, reports, and documents
* Supports:

  * `max_length`
  * `min_length`

# How Transformers Work

## Transformer Models

Transformer models can generally be grouped into 3 categories:

* **GPT-like** (*autoregressive*)
* **BERT-like** (*autoencoding*)
* **T5-like** (*sequence-to-sequence*)

Examples include:

* GPT
* BERT
* T5
* Llama
* Mistral
* Gemma
* SmolLM

## Transformers are Language Models

> 💡 Transformers are trained on massive amounts of text using self-supervised learning.

**Self-supervised learning** means:

* No manual labels are needed
* Training objectives are generated automatically from the data

Transformers first undergo:

1. **Pretraining**
2. **Fine-tuning**

## Language Modeling Tasks

### Causal Language Modeling

Predicts the next word using previous words only.

Example:

```txt
"The cat sat on the ___"
```

Used mainly by:

* GPT-style models

Key idea:

* Cannot see future words

### Masked Language Modeling

Predicts missing words in a sentence.

Example:

```txt
"The cat <mask> on the mat"
```

Used mainly by:

* BERT-style models

Key idea:

* Can use surrounding context

## Transformers are Large Models

Performance generally improves with:

* More parameters
* More training data

However, training large models requires:

* Huge datasets
* Expensive hardware
* Significant time
* High energy usage

Important concept:

* Sharing pretrained models reduces:

  * Compute cost
  * Financial cost
  * Environmental impact

## Transfer Learning

### Pretraining

> 💡 Pretraining trains a model from scratch on massive datasets.

Characteristics:

* Randomly initialized weights
* Very expensive
* Can take weeks

### Fine-Tuning

> 💡 Fine-tuning adapts a pretrained model to a specific task.

Benefits:

* Requires less data
* Faster training
* Lower cost
* Better results than training from scratch

Example:

* General English model → fine-tuned on scientific papers

This process is called **transfer learning** because knowledge learned during pretraining is transferred to new tasks.

## General Transformer Architecture

Transformers are made of two main components:

### Encoder

Purpose:

* Understand input text
* Extract features/representations

Good for:

* Classification
* Named Entity Recognition (NER)
* Understanding tasks

### Decoder

Purpose:

* Generate output text

Good for:

* Text generation
* Autocomplete
* Chatbots

### Encoder-Decoder Models

Also called:

* Sequence-to-sequence models

Good for:

* Translation
* Summarization

## Attention Layers

> 💡 Attention allows the model to focus on important words in context.

Key idea:

* Word meaning depends on surrounding words

Example:

```txt
"You like this course"
```

To translate `"like"` correctly, the model must pay attention to `"You"` because verb forms depend on the subject.

Attention helps models:

* Understand context
* Handle long-range dependencies
* Improve translation and reasoning

## Original Transformer Architecture

The original Transformer was designed for translation.

### Encoder

* Can attend to all words in the input sentence

### Decoder

* Generates words sequentially
* Can only see previously generated words
* Cannot access future words

This restriction is enforced using:

* **Attention masks**

Attention masks also:

* Ignore padding tokens during training

## Architecture vs Checkpoints

### Architecture

> 💡 The structure/design of the model.

Defines:

* Layers
* Operations
* Connections

Example:

* BERT

### Checkpoint

> 💡 The trained weights for an architecture.

Example:

* `bert-base-cased`

### Model

General term that may refer to:

* Architecture
* Checkpoint
* Both together

# How Transformers Solve Tasks

## Transformer Architectures

Most Transformer models are based on one of three architectures:

* **Encoder-only**
* **Decoder-only**
* **Encoder-decoder**

The general workflow is:

1. Input data is processed
2. Passed through a Transformer model
3. Output is interpreted for a specific task

Different tasks mainly differ in:

* Input formatting
* Model architecture
* Output processing

## Transformer Models for Language

> 💡 Language models learn statistical relationships between words to understand and generate language.

Transformers were originally created for machine translation but are now used for many NLP tasks.

### Language Model Training Approaches

#### Masked Language Modeling (MLM)

Used by encoder models like BERT.

The model:

* Randomly masks words
* Predicts missing tokens using surrounding context

Key feature:

* Bidirectional understanding

Example:

```txt id="1mknld"
"The cat <mask> on the mat"
```

#### Causal Language Modeling (CLM)

Used by decoder models like GPT.

The model:

* Predicts the next token
* Only uses previous tokens

Key feature:

* Left-to-right generation

Example:

```txt id="g0tgb2"
"The cat sat on the ___"
```

### Types of Language Models

#### Encoder-Only Models

Examples:

* BERT

Best for:

* Text classification
* Named Entity Recognition (NER)
* Question answering

These models understand context from both directions.

#### Decoder-Only Models

Examples:

* GPT
* Llama

Best for:

* Text generation
* Chatbots
* Code generation

These models generate text sequentially from left to right.

#### Encoder-Decoder Models

Examples:

* T5
* BART

Best for:

* Translation
* Summarization
* Sequence-to-sequence tasks

The encoder understands input while the decoder generates output.

## Transfer Learning

Transformer models are usually:

1. Pretrained on massive datasets
2. Fine-tuned for specific tasks

> 💡 Fine-tuning allows adapting large pretrained models using smaller task-specific datasets.

## NLP Tasks

### Text Generation

Text generation creates coherent text from a prompt.

#### GPT-2

GPT-2 is a decoder-only model trained using causal language modeling.

How it works:

1. Text is tokenized using **Byte Pair Encoding (BPE)**
2. Positional embeddings are added
3. Tokens pass through decoder blocks
4. Masked self-attention prevents access to future tokens
5. The model predicts the next token

Key points:

* Uses decoder-only architecture
* Excellent for generation tasks
* Generates text autoregressively

### Text Classification

Text classification assigns labels to text.

Examples:

* Sentiment analysis
* Spam detection
* Topic classification

#### BERT

BERT is an encoder-only model with bidirectional understanding.

Special tokens:

* `[CLS]` → classification token
* `[SEP]` → separates sentences

BERT pretraining tasks:

1. **Masked Language Modeling**
2. **Next Sentence Prediction**

For classification:

* Final hidden state of `[CLS]` is passed to a classification head
* Outputs logits for class prediction

### Token Classification

Token classification assigns labels to each token.

Examples:

* Named Entity Recognition (NER)
* Part-of-speech tagging

BERT performs this by:

* Passing hidden states through a token classification head
* Predicting labels for each token individually

### Question Answering

Question answering identifies an answer span within text.

BERT uses:

* A span classification head
* Predicts:

  * Start position
  * End position

The predicted span becomes the answer.

### Summarization

Summarization compresses long text while preserving important information.

### BART

BART is an encoder-decoder model designed for sequence-to-sequence tasks.

How it works:

1. Input text is corrupted/masked
2. Encoder processes corrupted text
3. Decoder reconstructs original text

Important technique:

* **Text infilling**

  * Multiple missing words replaced with one mask token

Benefits:

* Learns context reconstruction
* Strong summarization performance

### Translation

Translation converts text between languages.

Encoder-decoder models like:

* BART
* T5

are well suited because:

* Encoder understands source language
* Decoder generates target language

mBART extends this idea to multilingual translation.

Transformers can also process:

* Audio
* Images

Transformers can also solve computer vision tasks.

Two main approaches:

### Image Classification

Image classification predicts the class of an image.

### Vision Transformer (ViT)

ViT treats images similarly to text.

How it works:

1. Image split into patches
2. Patches converted into embeddings
3. `[CLS]` token added
4. Positional embeddings added
5. Passed through Transformer encoder

>
> * Both use `[CLS]`
> * Both use positional embeddings
> * Both rely on Transformer encoders

# Transformer Architectures

Transformer models generally use one of three architectures:

* Encoder-only
* Decoder-only
* Encoder-decoder (*sequence-to-sequence*)

Choosing the correct architecture depends on the task being solved.

## Encoder models

> 💡 Encoder models are designed for understanding text.

Encoder models use only the encoder component of a Transformer. Their attention layers can access all words in a sentence, making them *bidirectional*.

These models are usually pretrained by corrupting text, such as masking words, and training the model to reconstruct the original sentence.

Encoder models work best for tasks requiring full sentence understanding, including:

* Text classification
* Named Entity Recognition (NER)
* Token classification
* Extractive question answering

Examples include:

* BERT
* DistilBERT
* ModernBERT

## Decoder models

> 💡 Decoder models are designed for text generation.

Decoder models use only the decoder component of a Transformer. At each step, the model can only attend to previous tokens, making them *autoregressive*.

These models are typically pretrained by predicting the next word in a sequence.

Decoder models are best suited for:

* Text generation
* Conversational AI
* Code generation
* Autocomplete systems

Examples include:

* SmolLM
* Llama
* Gemma
* DeepSeek

### Modern Large Language Models (LLMs)

Most modern LLMs use decoder-only architectures.

Training usually occurs in two stages:

1. **Pretraining** on massive text datasets using next-token prediction
2. **Instruction tuning** to improve helpfulness and instruction following

Modern LLMs demonstrate capabilities such as:

* Text generation
* Summarization
* Translation
* Question answering
* Code generation
* Reasoning
* Few-shot learning

## Sequence-to-sequence models

> 💡 Sequence-to-sequence models both understand input and generate output.

Encoder-decoder models use both Transformer components:

* The encoder processes the entire input sequence
* The decoder generates output token-by-token

These models are often pretrained by corrupting text and reconstructing it.

For example, T5 replaces spans of text with a single mask token and predicts the missing content.

Sequence-to-sequence models are best suited for:

* Translation
* Summarization
* Generative question answering
* Grammar correction

Examples include:

* BART
* mBART
* Marian
* T5

### Practical applications

Sequence-to-sequence models are commonly used for transforming one text sequence into another while preserving meaning.

Typical applications include:

* Machine translation
* Text summarization
* Data-to-text generation
* Grammar correction
* Generative QA systems

## Choosing the right architecture

The best architecture depends on the task.

| Task                     | Best Architecture         | Example Models |
| ------------------------ | ------------------------- | -------------- |
| Text classification      | Encoder                   | BERT           |
| Text generation          | Decoder                   | GPT, Llama     |
| Translation              | Encoder-decoder           | T5, BART       |
| Summarization            | Encoder-decoder           | BART           |
| Named Entity Recognition | Encoder                   | BERT           |
| Extractive QA            | Encoder                   | BERT           |
| Generative QA            | Decoder / Encoder-decoder | GPT, T5        |
| Conversational AI        | Decoder                   | GPT, Llama     |

* Use **encoders** for understanding text
* Use **decoders** for generating text
* Use **encoder-decoders** for transforming sequences

## Attention mechanisms

> 💡 Standard attention has a computational complexity of O(n²), making long sequences expensive to process.

Some Transformer models use modified attention mechanisms to improve efficiency.

### LSH attention

Reformer uses **Locality Sensitive Hashing (LSH) attention**.

Key idea:

* Queries only attend to similar keys instead of all tokens

Benefits:

* Reduces computation
* Improves efficiency on long sequences

Multiple hash functions are typically used to reduce randomness.

### Local attention

Longformer uses **local attention**.

Key idea:

* Tokens mainly attend to nearby tokens within a local window

Some important tokens receive **global attention**, allowing access to the full sequence.

Benefits:

* Handles much longer inputs
* Reduces memory usage
* Maintains useful context

### Axial positional encodings

Reformer uses **axial positional encodings** to reduce memory usage.

Traditional positional embeddings can become extremely large for long sequences. Axial positional encoding factorizes one large embedding matrix into smaller matrices.

Benefits:

* Lower GPU memory usage
* Better scalability for long text

## Conclusion

Transformer models mainly fall into three categories:

* Encoder-only
* Decoder-only
* Encoder-decoder

Understanding these architectures helps determine which model is best suited for a task.

Specialized attention mechanisms such as:

* LSH attention
* Local attention
* Axial positional encodings

help Transformers scale more efficiently to long sequences.

# Deep dive into Text Generation Inference with LLMs

This section focuses on how Large Language Models (LLMs) generate text during inference. Inference is the process of using a trained model to produce text from a prompt.

## Understanding the Basics

LLMs generate text one token at a time. A token can be a word, part of a word, or punctuation. The model predicts the most likely next token based on the previous tokens and its learned knowledge from training.

The model relies on billions of learned parameters to generate coherent and contextually relevant responses. Text generation is sequential because each new token depends on the tokens generated before it.

## The Role of Attention

Attention allows the model to focus on the most relevant words in a sequence when predicting the next token. For example, in the sentence “The capital of France is ...”, the words “capital” and “France” strongly influence the prediction of “Paris”.

Attention helps the model understand relationships between words and maintain context across long sequences. This mechanism is one of the key reasons modern LLMs are effective at generating coherent text.

### Context Length and Attention Span

Context length is the maximum number of tokens the model can process at once. It acts like the model’s working memory.

The context length depends on:

* The model architecture
* Available compute resources
* Input and output complexity

Longer contexts improve understanding but increase computational and memory costs.

## The Art of Prompting

Prompting is the process of structuring input text to guide the model toward the desired response.

Since LLMs predict the next token based on the input sequence, prompt wording greatly affects the output. Clear and well-structured prompts generally produce better responses.

## The Two-Phase Inference Process

LLM inference consists of two main phases: prefill and decode.

### The Prefill Phase

The prefill phase processes the input prompt before generation begins. It involves:

1. Tokenizing the input text
2. Converting tokens into embeddings
3. Passing embeddings through the neural network to build contextual understanding

This phase is computationally expensive because all input tokens are processed together.

### The Decode Phase

The decode phase generates text one token at a time using an autoregressive process.

For each generated token, the model:

1. Computes attention over previous tokens
2. Calculates token probabilities
3. Selects the next token
4. Decides whether generation should continue

This phase is memory-intensive because the model must track all previous tokens and their relationships.

## Sampling Strategies

Sampling strategies control how the model selects the next token during generation.

### Understanding Token Selection

The model first produces raw probabilities called logits for every possible token.

Several techniques adjust these probabilities:

1. **Temperature** controls randomness. Higher values increase creativity, while lower values make outputs more deterministic.
2. **Top-p sampling** selects from the smallest group of tokens whose cumulative probability reaches a threshold.
3. **Top-k sampling** limits selection to the top k most likely tokens.

These methods balance creativity and coherence.

### Managing Repetition

LLMs can repeat words or phrases, so penalties are used to encourage variety.

1. **Presence penalty** discourages reuse of tokens that already appeared.
2. **Frequency penalty** increasingly penalizes tokens that appear multiple times.

These penalties modify token probabilities before sampling occurs.

### Controlling Generation Length

Generation length can be controlled using:

1. Minimum and maximum token limits
2. Stop sequences
3. End-of-sequence tokens

These controls help keep outputs concise and relevant.

### Beam Search

Beam search explores multiple possible token sequences at the same time instead of choosing only one path.

The process:

1. Maintains several candidate sequences
2. Expands each candidate with likely next tokens
3. Keeps only the most promising sequences
4. Continues until generation stops

Beam search often produces more coherent outputs but requires more computation.

## Practical Challenges and Optimization

Deploying LLMs involves balancing performance, memory usage, and speed.

### Key Performance Metrics

Important inference metrics include:

1. **Time to First Token (TTFT):** Delay before the first generated token
2. **Time Per Output Token (TPOT):** Speed of generating additional tokens
3. **Throughput:** Number of requests handled simultaneously
4. **VRAM Usage:** GPU memory consumption

These metrics strongly affect user experience and deployment cost.

### The Context Length Challenge

Longer contexts provide more information but create major computational costs:

* Memory usage grows approximately quadratically with sequence length
* Processing time increases with longer inputs
* GPU memory requirements become much higher

Models with very large context windows are powerful but slower and more resource-intensive.

### The KV Cache Optimization

KV caching stores intermediate attention computations so they can be reused during decoding.

Benefits include:

* Reduced repeated computation
* Faster token generation
* Improved long-context performance

The trade-off is increased memory usage, but the performance gains are usually worth it.

## Conclusion

LLM inference involves predicting tokens sequentially using attention and contextual understanding. The process consists of:

* Attention-based context handling
* Prefill and decode phases
* Sampling and decoding strategies
* Performance optimizations such as KV caching

Understanding these concepts is important for deploying efficient and effective LLM applications.

# Bias and limitations

Pretrained and fine-tuned Transformer models are powerful, but they also have important limitations. Many models are trained on massive datasets collected from the internet, which includes both useful and harmful content.

Because of this, models can learn and reproduce social biases found in the training data.

For example, a BERT `fill-mask` model may associate certain professions with specific genders:

* “This man works as a [MASK]” may produce outputs like lawyer, doctor, or mechanic.
* “This woman works as a [MASK]” may produce outputs like nurse, maid, or prostitute.

These predictions reflect patterns learned from the training data rather than objective truth.

Bias can appear even in models trained on relatively neutral datasets such as:

* English Wikipedia
* BookCorpus

As a result, Transformer models may generate:

* Sexist content
* Racist content
* Homophobic content
* Other harmful or stereotypical outputs

Fine-tuning a model on custom data may reduce some issues, but it does not completely remove the original biases learned during pretraining.

When deploying Transformer models in production, it is important to:

* Be aware of potential biases
* Evaluate outputs carefully
* Monitor harmful generations
* Apply safety and moderation strategies where needed
